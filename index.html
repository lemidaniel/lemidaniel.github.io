CS / 001

Understanding an SMS delivery path

A reference case study for tracing a message from an application through a gateway and upstream SMSC, then reconciling delivery reports.

Problem to investigate

When sent-message counts and delivery-report counts differ, determine whether the cause is timing, retries, duplicate submissions, status mapping, or reporting logic.

Investigation approach

Trace a single test message with a safe correlation identifier. Compare gateway logs, outbound records, SMSC responses, and DLR events across a defined time window.

How to verify

Use a controlled test set, define what each status means, account for delayed reports, and compare unique message IDs rather than relying on raw row totals alone.

CS / 002

Investigating database connection usage

A repeatable way to inspect PostgreSQL sessions and understand whether connection counts are expected or excessive.

SQL / SESSION SUMMARY
SELECT state, count(*) AS sessions
FROM pg_stat_activity
WHERE datname = current_database()
GROUP BY state
ORDER BY sessions DESC;

Look at

Session state, application name, client address, query age, pool configuration, and PostgreSQL connection limits.

Verify

Compare database sessions with application pool settings and expected traffic. Avoid terminating sessions without understanding their owner and impact.

Understanding Linux LVM paths

A path such as /dev/mapper/ubuntu--vg-ubuntu--lv typically identifies a logical volume managed by Linux device mapper. The doubled hyphens escape hyphens in the volume-group and logical-volume names. In this example, the names are commonly ubuntu-vg and ubuntu-lv.

lsblk
sudo pvs
sudo vgs
sudo lvs
 df -hT /

Use lsblk to see the block-device hierarchy, lvs to inspect logical volumes, and df -hT / to inspect the filesystem mounted at root. Disk capacity and free space inside a filesystem are related but not identical to unused space in the volume group.

NOTE / 002Back to notes ↑

Sent SMS vs. delivery reports

A delivery report is a separate event from submitting a message. DLR totals can differ from sent totals because of delayed reports, retries, repeated status events, date-window differences, or counting methods. A report count alone is not a reliable success rate.

  • Choose a defined time window and timezone.
  • Count unique outbound message identifiers where possible.
  • Separate delivered, failed, rejected, pending, and unknown states.
  • Compare gateway submissions with SMSC responses and DLR events.

Document how each status is defined before publishing a delivery percentage. Use sanitized sample data in public examples.

Inspecting PostgreSQL sessions

The pg_stat_activity view provides a snapshot of backend activity. Grouping sessions by state is a useful first step, but a large idle count is not automatically a problem. Check whether the application uses a connection pool and whether sessions are expected for its workload.

SELECT state, count(*) AS sessions
FROM pg_stat_activity
WHERE datname = current_database()
GROUP BY state
ORDER BY sessions DESC;

Before terminating a session or changing limits, identify its application, user, query age, and operational impact. In production, follow the approved change process.
